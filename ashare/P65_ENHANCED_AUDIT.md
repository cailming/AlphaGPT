# P6.5-B 增强模型运行诊断

`p65_enhanced_audit.py` 核对原 V2 与六方法账本的同日档案、候选来源、公司行为观察、风险事件文件、训练归一化和权重散列。它从 PostgreSQL 的只读正式行情快照重算特征，复用冻结的因子序列定义和信号日正式行情边界。输出独立的诊断归档，不产生及时预测或未来标签。

```bash
conda run -n py312 python -m ashare.p65_enhanced_audit \
  --legacy "$previous/ledger" --panel "$follow/panel" \
  --source "$previous/paired18" --full18 "$previous/stable_models/factors18" \
  --group-model "$follow/ablation/models/group_c" --group-ledger "$research/group_c" \
  --out "$new_audit" --compare 2026-09-23
```

`enhanced_audit.json` 保存现有与假设资格计数、弃权原因、权重散列及历史完整输入的同股分数比较。三个缺值因子的实际输入日见 `latest_missing_factor_dates.csv`，通过原公司行为和因果历史检查的基础候选明细见 `latest_factor_candidates.csv`。运行在盘后需要先等最新正式日的原冻结候选档案发布。

C 组在训练时对整个 18 列做训练集标准化，再将 6 个未启用的标准化输入置零。假设规则把 12 个活跃列放入同一个 18 维投影，保持其余列在标准化空间为零，且拒绝活跃列缺值。活跃列 `stock_relative_ret_20` 使用 `market_ret_20` 计算，因此市场 20 日收益即使在 C 组输入投影中被掩掉，也需要在因子构建时完整可用。

截至北京时间 2026-11-27 14:13，最新正式行情为 11 月 26 日。252 只候选中，236 只满足基础检查，18 因子、冻结 C 和只检查活跃列的假设规则均为 0。市场 20 日收益、市场 20 日成交活跃度和个股相对强弱各缺失 1,652 个股票日，涉及 11 月 5、6、9、10、11、12、13 日。仅因未启用列被拒绝的股票数为 0。9 月 23 日历史诊断的 120 条完整序列上，C 组两种构造的输入张量和预测分数逐位一致，两套增强模型的重算分数与已归档分数也逐位一致。保留原规则并继续观察市场窗口自然恢复。另行启用一套活跃列资格需独立冻结及前瞻账本。
